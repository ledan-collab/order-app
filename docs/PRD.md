# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면

브랜드명은 COZY다. 주문하기 화면은 앱의 기본 화면이며, 사용자가 메뉴와 옵션을 골라 장바구니에 담고 주문한다.

화면은 위에서 아래로 헤더, 메뉴 목록, 장바구니 세 영역이다.

### 4.1 헤더

| 요소 | 내용 | 동작 |
| --- | --- | --- |
| 브랜드 | COZY | 표시만 한다 |
| 화면 이동 | 주문하기 | 현재 화면. 배경색으로 선택된 상태임을 보여 준다 |
| 화면 이동 | 관리자 | 관리자 화면으로 이동한다. 상세 요구사항은 5장에 둔다 |

### 4.2 메뉴 목록

메뉴는 카드로 보여 주고, 와이어프레임처럼 한 줄에 나란히 놓는다. 카드 내용은 위에서 아래로 다음 순서다.

1. 메뉴 이미지 영역
2. 메뉴 이름
3. 기본 가격
4. 재고 수량과 상태
5. 짧은 설명
6. 옵션 체크박스
7. 담기 버튼

재고는 `{수량}개`와 상태를 가로로 나란히 보여 준다. 5개 이상은 `정상`, 1개 이상 4개 이하는 `주의`, 0개는 `품절`이다. 재고가 0이면 담기 버튼을 누를 수 없다.

화면에 처음 보여 주는 메뉴는 아래와 같다. 설명은 와이어프레임의 자리 표시 문구를 그대로 쓴다.

| 메뉴 이름 | 기본 가격 | 설명 |
| --- | --- | --- |
| 아메리카노(ICE) | 4,000원 | 간단한 설명... |
| 아메리카노(HOT) | 4,000원 | 간단한 설명... |
| 카페라떼 | 5,000원 | 간단한 설명... |

모든 메뉴에 같은 옵션을 둔다.

| 옵션 | 추가 금액 | 기본값 |
| --- | --- | --- |
| 샷 추가 | +500원 | 해제 |
| 시럽 추가 | +0원 | 해제 |

- 체크박스는 카드마다 따로 둔다. 한 카드의 선택은 다른 카드와 장바구니에 바로 반영되지 않는다.
- 두 옵션은 독립이다. 둘 다 선택, 하나만 선택, 아무 것도 선택하지 않은 상태를 모두 허용한다.
- 금액은 천 단위를 구분하고 `원`을 붙인다. 예: `4,000원`, `(+500원)`, `(+0원)`
- 메뉴 이미지가 없으면 와이어프레임과 같이 빈 이미지 영역을 보여 준다.

### 4.3 장바구니

장바구니는 메뉴 목록 아래의 한 영역이다. 왼쪽에는 담긴 항목, 오른쪽에는 총 금액과 주문하기 버튼을 둔다.

항목 한 줄에 보여 주는 내용:

- 메뉴 이름
- 선택한 옵션. 하나 이상이면 이름 뒤에 공백과 괄호로 붙인다.
- 수량. `X {수량}` 형식
- 줄 금액. 단가 × 수량

옵션 표시 예:

- 샷만 선택: `아메리카노(ICE) (샷 추가)`
- 옵션 없음: `아메리카노(HOT)`
- 둘 다 선택: `아메리카노(ICE) (샷 추가, 시럽 추가)`

옵션 나열 순서는 카드의 체크박스 순서(샷 추가, 시럽 추가)를 따른다.

와이어프레임에 그려진 장바구니 예시다.

| 항목 | 수량 | 줄 금액 |
| --- | --- | --- |
| 아메리카노(ICE) (샷 추가) | 1 | 4,500원 |
| 아메리카노(HOT) | 2 | 8,000원 |
| 총 금액 |  | 12,500원 |

이 예시의 계산은 다음과 같다.

- 아메리카노(ICE) 4,000원 + 샷 추가 500원 = 4,500원, 수량 1
- 아메리카노(HOT) 4,000원 × 2 = 8,000원
- 총 금액 4,500원 + 8,000원 = 12,500원

### 4.4 담기

- 담기를 누르면 그 카드의 메뉴와 현재 선택된 옵션을 수량 1로 장바구니에 넣는다.
- 메뉴와 옵션 구성이 같은 줄이 이미 있으면 그 줄의 수량을 1 올린다.
- 메뉴가 같아도 옵션 구성이 다르면 새 줄로 담는다.
- 담은 뒤에는 해당 카드의 옵션을 모두 해제한다.
- 옵션을 고르지 않아도 담을 수 있다.

### 4.5 금액

- 단가 = 기본 가격 + 선택된 옵션 추가 금액의 합
- 줄 금액 = 단가 × 수량
- 총 금액 = 모든 줄 금액의 합
- 장바구니 내용이 바뀌면 줄 금액과 총 금액을 바로 다시 계산해 보여 준다.
- 시럽 추가(+0원)를 골라도 줄의 옵션 이름에는 포함한다.
- 같은 메뉴는 옵션이 달라도 재고를 함께 쓴다. 장바구니에 담긴 수량의 합이 재고와 같으면 담기와 수량 증가를 할 수 없다.
- 수량은 `−`와 `+`로 바꾼다. 수량이 1일 때 `−`를 누르면 그 줄을 장바구니에서 뺀다.

### 4.6 주문하기

- 장바구니에 항목이 있고, 담긴 수량이 재고를 넘지 않을 때 주문하기를 누르면, 현재 장바구니의 항목·옵션·수량·줄 금액·총 금액으로 주문을 저장한다.
- 저장에 성공하면 장바구니를 비우고, `주문이 접수되었습니다.`를 보여 준다. 저장한 수량만큼 해당 메뉴 재고를 줄인다.
- 장바구니가 비어 있거나 담긴 수량이 재고보다 많으면 주문하기 버튼은 누를 수 없다. 재고가 부족하면 `담긴 수량이 재고보다 많아 주문할 수 없습니다.`를 보여 준다.
- 장바구니가 비어 있으면 `장바구니가 비어 있습니다.`를 보여 주고, 총 금액은 `0원`이다.
- 주문자 정보와 결제는 받지 않는다.

### 4.7 화면 상태

| 상태 | 장바구니 | 총 금액 | 주문하기 버튼 |
| --- | --- | --- | --- |
| 처음 진입, 또는 주문 저장 직후 | 항목 없음. `장바구니가 비어 있습니다.`를 보여 주고 장바구니 영역은 유지 | 0원 | 비활성 |
| 항목이 하나 이상이고 재고가 충분 | 담은 순서대로 표시 | 줄 금액의 합 | 활성 |
| 담긴 수량이 재고보다 많음 | 담은 순서대로 표시하고 재고 부족 안내를 보여 준다 | 줄 금액의 합 | 비활성 |

메뉴 카드의 옵션은 화면 진입 시와 담기 직후 모두 해제 상태다.

### 4.8 이 화면의 범위

이 화면 요구사항에 포함하는 것:

- 메뉴 카드 표시, 옵션 선택, 장바구니 담기, 금액 계산, 주문 저장
- 헤더에서 관리자 화면으로 이동

서버 API의 경로와 요청 형식은 6장에 둔다.

## 5. 관리자 화면

관리자 화면은 주문 집계를 보고, 메뉴 재고를 조정하고, 주문을 다음 단계로 넘긴다. 헤더의 관리자를 누르면 이 화면으로 들어온다.

화면은 위에서 아래로 헤더, 관리자 대시보드, 재고 현황, 주문 현황 네 영역이다.

### 5.1 헤더

주문하기 화면과 같은 헤더다. 이 화면에서는 관리자만 배경색으로 선택된 상태임을 보여 준다. 주문하기를 누르면 주문하기 화면으로 이동한다.

### 5.2 관리자 대시보드

제목은 `관리자 대시보드`다. 아래에 주문 수를 한 줄로 보여 준다.

`총 주문 {총수} / 주문 접수 {접수 수} / 제조 중 {제조 수} / 제조 완료 {완료 수}`

| 항목 | 집계 |
| --- | --- |
| 총 주문 | 저장된 주문 전체 수 |
| 주문 접수 | 상태가 주문 접수인 주문 수 |
| 제조 중 | 상태가 제조 중인 주문 수 |
| 제조 완료 | 상태가 제조 완료인 주문 수 |

와이어프레임 예시는 `총 주문 1 / 주문 접수 1 / 제조 중 0 / 제조 완료 0`이다. 주문이 없으면 네 값 모두 0이다. 주문 상태가 바뀌거나 새 주문이 생기면 집계를 바로 다시 보여 준다.

### 5.3 재고 현황

제목은 `재고 현황`이다. 주문하기 화면의 메뉴 3개를 카드로 한 줄에 나란히 놓는다.

카드 내용은 위에서 아래로 메뉴 이름, 재고 수량, 증가 버튼, 감소 버튼이다.

| 메뉴 이름 | 처음 재고 |
| --- | --- |
| 아메리카노(ICE) | 10개 |
| 아메리카노(HOT) | 10개 |
| 카페라떼 | 10개 |

- 수량은 `{수량}개`로 보여 준다. 예: `10개`
- `+`를 누르면 해당 메뉴 재고가 1 늘어난다.
- `-`를 누르면 해당 메뉴 재고가 1 줄어든다.
- 재고가 0이면 `-`는 누를 수 없다.
- 버튼을 누른 직후 카드의 수량을 다시 보여 준다.
- 수량 옆에 상태를 가로로 보여 준다. 5개 이상은 `정상`, 1개 이상 4개 이하는 `주의`, 0개는 `품절`이다.

### 5.4 주문 현황

제목은 `주문 현황`이다. 주문하기 화면에서 저장된 주문을 목록으로 보여 준다. 최신 주문이 위에 온다. 주문이 없어도 이 영역은 유지하고, 목록만 비어 있다.

한 줄은 왼쪽부터 주문 시각, 주문 내용, 금액, 현재 상태, 상태 버튼이다.

와이어프레임에 그려진 주문 예시다.

| 주문 시각 | 주문 내용 | 금액 | 상태 버튼 |
| --- | --- | --- | --- |
| 7월 31일 13:00 | 아메리카노(ICE) x 1 | 4,000원 | 주문 접수 |

표시 규칙:

- 주문 시각은 `M월 D일 HH:mm`이다. 연도는 보여 주지 않고, 시는 24시간제다.
- 주문 내용의 메뉴 한 개는 `{메뉴 이름} x {수량}`이다. 옵션이 있으면 주문하기 화면 장바구니와 같은 이름으로 보여 준다. 예: `아메리카노(ICE) (샷 추가) x 1`
- 한 주문에 메뉴가 여러 개면 쉼표와 공백으로 한 줄에 잇는다. 예: `아메리카노(ICE) (샷 추가) x 1, 아메리카노(HOT) x 2`
- 금액은 그 주문의 총 금액이며, 천 단위를 구분하고 `원`을 붙인다.

### 5.5 주문 상태

주문은 저장되는 순간 `주문 접수`다. 한 줄에는 현재 상태 이름과 다음 단계로 넘기는 버튼을 함께 보여 준다. 버튼을 누르면 다음 상태로 한 단계 넘어가고, 대시보드 집계도 함께 바뀐다.

| 현재 상태 | 상태 표시 | 버튼 문구 | 버튼을 누른 뒤 |
| --- | --- | --- | --- |
| 주문 접수 | 주문 접수 | 제조 시작 | 제조 중 |
| 제조 중 | 제조 중 | 제조 완료 | 제조 완료 |
| 제조 완료 | 제조 완료 | 제조 완료 | 더 이상 누르지 못한다 |

제조 완료인 주문은 목록에 그대로 남는다.

### 5.6 화면 상태

| 상태 | 대시보드 | 재고 현황 | 주문 현황 |
| --- | --- | --- | --- |
| 주문이 없을 때 | 총 주문 0 / 주문 접수 0 / 제조 중 0 / 제조 완료 0 | 메뉴별 현재 재고 | 빈 목록 |
| 주문이 있을 때 | 상태별 주문 수 | 메뉴별 현재 재고 | 최신 주문이 위 |

### 5.7 이 화면의 범위

이 화면 요구사항에 포함하는 것:

- 주문 수 집계
- 메뉴 재고를 1개씩 늘리거나 줄이기
- 주문 목록 표시와 상태 진행(주문 접수, 제조 중, 제조 완료)
- 헤더에서 주문하기 화면으로 이동

서버 API의 경로와 요청 형식은 6장에 둔다.

## 6. 백엔드

백엔드는 Node.js와 Express로 JSON API를 제공하고, PostgreSQL에 메뉴, 옵션, 주문을 저장한다. 인증과 결제는 없다. 장바구니는 브라우저 상태에만 두고 데이터베이스에는 저장하지 않는다.

금액은 원 단위 정수다. 시각은 ISO 8601로 주고받는다. 오류 응답은 `{ "message": "설명" }`이다.

### 6.1 데이터 모델

#### Menus

커피 메뉴 한 개다.

| 필드 | 내용 |
| --- | --- |
| id | 메뉴 식별자 |
| name | 커피 이름 |
| description | 설명 |
| price | 가격 |
| image | 이미지 경로 |
| stock | 재고 수량. 0 이상의 정수 |

#### Options

메뉴에 붙는 옵션이다. 한 옵션은 하나의 메뉴에 연결한다. 같은 이름이어도 메뉴가 다르면 다른 행이다.

| 필드 | 내용 |
| --- | --- |
| id | 옵션 식별자 |
| menu_id | 연결할 메뉴. Menus의 id |
| name | 옵션 이름 |
| price | 옵션 가격. 0원도 허용 |

처음 넣는 데이터는 메뉴 3개마다 샷 추가 500원, 시럽 추가 0원을 연결한다.

#### Orders

주문 한 건이다. 주문 내용의 메뉴, 수량, 옵션, 금액은 이 주문에 속한 줄로 저장한다.

| 필드 | 내용 |
| --- | --- |
| id | 주문 식별자 |
| ordered_at | 주문 일시. 서버가 저장하는 시각 |
| status | `주문 접수`, `제조 중`, `완료`. 기본값은 `주문 접수` |
| total | 주문 금액 합계 |

주문 내용 한 줄:

| 필드 | 내용 |
| --- | --- |
| id | 줄 식별자 |
| order_id | 속한 주문 |
| menu_id | 주문한 메뉴 |
| menu_name | 주문 당시의 커피 이름 |
| quantity | 수량. 1 이상 |
| option_names | 선택한 옵션 이름. 없으면 빈 목록 |
| option_prices | 주문 당시의 옵션 가격. option_names와 같은 순서 |
| line_price | 그 줄의 금액. (메뉴 가격 + 옵션 가격 합) × 수량 |

이름과 가격은 주문 당시 값을 함께 남긴다. 나중에 메뉴나 옵션 가격이 바뀌어도 이미 저장된 주문 금액은 유지한다.

처음 넣는 메뉴는 다음과 같다. 이미지는 프런트가 제공하는 경로를 저장한다.

| 커피 이름 | 설명 | 가격 | 이미지 | 재고 |
| --- | --- | --- | --- | --- |
| 아메리카노(ICE) | 에스프레소에 찬물을 더해 깔끔하게 마시는 아이스 커피 | 4,000원 | `/images/americano-ice.jpg` | 10 |
| 아메리카노(HOT) | 뜨거운 물에 에스프레소를 더한 기본 커피 | 4,000원 | `/images/americano-hot.jpg` | 10 |
| 카페라떼 | 에스프레소와 스팀 밀크를 부드럽게 섞은 라떼 | 5,000원 | `/images/cafe-latte.jpg` | 10 |

### 6.2 데이터 스키마를 위한 사용자 흐름

1. 주문하기 화면을 열면 Menus와 연결된 Options를 읽어 카드에 표시한다. Menus의 재고 수량은 관리자 화면의 재고 현황에 표시한다. 주문하기 화면은 같은 재고로 4.2와 4.5의 품절, 주의, 담기 가능 여부를 판단한다.
2. 사용자가 커피 메뉴와 옵션을 골라 담으면 그 선택은 장바구니에 표시한다. 담기, 수량 변경, 줄 삭제는 데이터베이스를 바꾸지 않는다.
3. 장바구니에서 주문하기를 누르면 주문 일시와 주문 내용(메뉴, 수량, 옵션, 금액)을 Orders에 저장한다. 상태는 `주문 접수`다. 같은 처리에서 메뉴별 수량만큼 Menus의 재고를 줄인다. 같은 메뉴를 옵션만 달리해 여러 줄로 담았으면 수량을 합쳐 한 번만 줄인다. 재고가 부족하면 주문 저장과 재고 변경을 모두 하지 않는다.
4. Orders를 관리자 화면의 주문 현황에 표시한다. 최신 주문이 위에 온다. 기본 상태는 `주문 접수`다. 관리자가 그 주문을 진행하면 `제조 중`이 되고, 다시 진행하면 `완료`가 된다. `완료` 이후에는 상태를 바꾸지 않는다. 5.5의 버튼 문구를 따르며, 화면의 `제조 완료`는 저장된 상태 `완료`와 같다.

### 6.3 API 설계

기본 경로는 `/api`다. 주문 금액은 요청에 담긴 금액을 그대로 저장하지 않고, 서버가 Menus.price와 Options.price로 다시 계산한다.

#### 메뉴 목록 조회

`GET /api/menus`

주문하기를 열면 데이터베이스에서 커피 메뉴 목록을 불러온다. 각 메뉴에 연결된 옵션과 재고 수량을 함께 돌려준다.

`200` 응답 예:

```json
[
  {
    "id": 1,
    "name": "아메리카노(ICE)",
    "description": "에스프레소에 찬물을 더해 깔끔하게 마시는 아이스 커피",
    "price": 4000,
    "image": "/images/americano-ice.jpg",
    "stock": 10,
    "options": [
      { "id": 1, "name": "샷 추가", "price": 500 },
      { "id": 2, "name": "시럽 추가", "price": 0 }
    ]
  }
]
```

#### 주문 저장

`POST /api/orders`

사용자가 커피를 장바구니에 담은 뒤 주문하기를 누르면 주문 정보를 데이터베이스에 저장한다. 주문 정보에 따라 해당 메뉴의 재고도 함께 수정한다. 저장과 재고 감소는 하나의 처리로 끝낸다.

요청 예:

```json
{
  "items": [
    { "menuId": 1, "optionIds": [1], "quantity": 1 },
    { "menuId": 2, "optionIds": [], "quantity": 2 }
  ]
}
```

`201` 응답 예:

```json
{
  "id": 1,
  "orderedAt": "2026-07-31T04:00:00.000Z",
  "status": "주문 접수",
  "total": 12500,
  "items": [
    {
      "menuId": 1,
      "menuName": "아메리카노(ICE)",
      "quantity": 1,
      "optionNames": ["샷 추가"],
      "linePrice": 4500
    },
    {
      "menuId": 2,
      "menuName": "아메리카노(HOT)",
      "quantity": 2,
      "optionNames": [],
      "linePrice": 8000
    }
  ]
}
```

이 예의 주문 시각 `2026-07-31T04:00:00.000Z`는 한국 시간 7월 31일 13:00이다.

실패:

| 상태 | 조건 |
| --- | --- |
| 400 | 항목이 없거나, 수량이 1보다 작거나, 옵션이 그 메뉴에 연결되어 있지 않음 |
| 404 | 없는 메뉴 |
| 409 | 재고가 주문 수량보다 적음. 주문과 재고는 그대로 둔다 |

#### 주문 하나 조회

`GET /api/orders/:id`

주문 ID를 전달하면 해당 주문 정보를 보여 준다. 응답 필드 구성은 주문 저장의 `201` 응답과 같다. 없는 ID는 `404`다.

#### 관리자 화면용 API

주문 현황, 상태 변경, 재고 증감은 5장의 화면을 위해 다음을 추가한다.

`GET /api/orders`

저장된 주문을 `orderedAt`의 내림차순으로 돌려준다. 각 항목의 필드는 주문 하나 조회와 같다. 주문이 없으면 빈 배열이다.

`PATCH /api/orders/:id`

상태를 한 단계만 바꾼다. `주문 접수`는 `제조 중`, `제조 중`은 `완료`가 된다. 본문은 비워 둔다. 성공하면 `200`과 변경된 주문을 돌려준다. 이미 `완료`이거나 없는 주문은 각각 `409`, `404`다.

`PATCH /api/menus/:id/stock`

관리자 화면의 `+`, `−`다. 본문은 `{ "delta": 1 }` 또는 `{ "delta": -1 }`만 허용한다. 성공하면 `200`과 변경된 메뉴를 돌려준다. 결과가 0보다 작거나 delta가 1, -1이 아니면 `400`이고 재고는 바꾸지 않는다.
