# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면

브랜드명은 COZY다. 주문하기 화면은 앱의 기본 화면이며, 사용자가 메뉴와 옵션을 골라 장바구니에 담고 주문한다.

화면은 위에서 아래로 헤더, 메뉴 목록, 장바구니 세 영역이다.

### 4.1 헤더

| 요소 | 내용 | 동작 |
| --- | --- | --- |
| 브랜드 | COZY | 표시만 한다 |
| 화면 이동 | 주문하기 | 현재 화면. 테두리로 선택된 상태임을 보여 준다 |
| 화면 이동 | 관리자 | 관리자 화면으로 이동한다. 상세 요구사항은 5장에 둔다 |

### 4.2 메뉴 목록

메뉴는 카드로 보여 주고, 와이어프레임처럼 한 줄에 나란히 놓는다. 카드 내용은 위에서 아래로 다음 순서다.

1. 메뉴 이미지 영역
2. 메뉴 이름
3. 기본 가격
4. 짧은 설명
5. 옵션 체크박스
6. 담기 버튼

화면에 처음 보여 주는 메뉴는 아래와 같다. 설명은 와이어프레임의 자리 표시 문구를 그대로 쓴다.

| 메뉴 이름 | 기본 가격 | 설명 |
| --- | --- | --- |
| 아메리카노(ICE) | 4,000원 | 간단한 설명... |
| 아메리카노(HOT) | 4,000원 | 간단한 설명... |
| 카페라떼 | 5,000원 | 간단한 설명... |

모든 메뉴에 같은 옵션을 둔다.

| 옵션 | 추가 금액 | 기본값 |
| --- | --- | --- |
| 샷 추가 | +500원 | 해제 |
| 시럽 추가 | +0원 | 해제 |

- 체크박스는 카드마다 따로 둔다. 한 카드의 선택은 다른 카드와 장바구니에 바로 반영되지 않는다.
- 두 옵션은 독립이다. 둘 다 선택, 하나만 선택, 아무 것도 선택하지 않은 상태를 모두 허용한다.
- 금액은 천 단위를 구분하고 `원`을 붙인다. 예: `4,000원`, `(+500원)`, `(+0원)`
- 메뉴 이미지가 없으면 와이어프레임과 같이 빈 이미지 영역을 보여 준다.

### 4.3 장바구니

장바구니는 메뉴 목록 아래의 한 영역이다. 왼쪽에는 담긴 항목, 오른쪽에는 총 금액과 주문하기 버튼을 둔다.

항목 한 줄에 보여 주는 내용:

- 메뉴 이름
- 선택한 옵션. 하나 이상이면 이름 뒤에 공백과 괄호로 붙인다.
- 수량. `X {수량}` 형식
- 줄 금액. 단가 × 수량

옵션 표시 예:

- 샷만 선택: `아메리카노(ICE) (샷 추가)`
- 옵션 없음: `아메리카노(HOT)`
- 둘 다 선택: `아메리카노(ICE) (샷 추가, 시럽 추가)`

옵션 나열 순서는 카드의 체크박스 순서(샷 추가, 시럽 추가)를 따른다.

와이어프레임에 그려진 장바구니 예시다.

| 항목 | 수량 | 줄 금액 |
| --- | --- | --- |
| 아메리카노(ICE) (샷 추가) | 1 | 4,500원 |
| 아메리카노(HOT) | 2 | 8,000원 |
| 총 금액 |  | 12,500원 |

이 예시의 계산은 다음과 같다.

- 아메리카노(ICE) 4,000원 + 샷 추가 500원 = 4,500원, 수량 1
- 아메리카노(HOT) 4,000원 × 2 = 8,000원
- 총 금액 4,500원 + 8,000원 = 12,500원

### 4.4 담기

- 담기를 누르면 그 카드의 메뉴와 현재 선택된 옵션을 수량 1로 장바구니에 넣는다.
- 메뉴와 옵션 구성이 같은 줄이 이미 있으면 그 줄의 수량을 1 올린다.
- 메뉴가 같아도 옵션 구성이 다르면 새 줄로 담는다.
- 담은 뒤에는 해당 카드의 옵션을 모두 해제한다.
- 옵션을 고르지 않아도 담을 수 있다.

### 4.5 금액

- 단가 = 기본 가격 + 선택된 옵션 추가 금액의 합
- 줄 금액 = 단가 × 수량
- 총 금액 = 모든 줄 금액의 합
- 장바구니 내용이 바뀌면 줄 금액과 총 금액을 바로 다시 계산해 보여 준다.
- 시럽 추가(+0원)를 골라도 줄의 옵션 이름에는 포함한다.

### 4.6 주문하기

- 장바구니에 항목이 있을 때 주문하기를 누르면, 현재 장바구니의 항목·옵션·수량·줄 금액·총 금액으로 주문을 저장한다.
- 저장에 성공하면 장바구니를 비운다.
- 장바구니가 비어 있으면 주문하기 버튼은 누를 수 없고, 총 금액은 `0원`으로 보여 준다.
- 주문자 정보와 결제는 받지 않는다.

### 4.7 화면 상태

| 상태 | 장바구니 | 총 금액 | 주문하기 버튼 |
| --- | --- | --- | --- |
| 처음 진입, 또는 주문 저장 직후 | 항목 없음. 장바구니 영역은 유지 | 0원 | 비활성 |
| 항목이 하나 이상 | 담은 순서대로 표시 | 줄 금액의 합 | 활성 |

메뉴 카드의 옵션은 화면 진입 시와 담기 직후 모두 해제 상태다.

### 4.8 이 화면의 범위

이 화면 요구사항에 포함하는 것:

- 메뉴 카드 표시, 옵션 선택, 장바구니 담기, 금액 계산, 주문 저장
- 헤더에서 관리자 화면으로 이동

이 문서 다음에 따로 정할 것:

- 서버 API의 경로와 요청 형식
- 장바구니 항목을 빼거나 수량을 줄이는 조작. 와이어프레임에는 해당 컨트롤이 없다
- 주문 저장 성공을 알림으로 보여 줄지
- 주문하면 재고가 함께 줄어드는지, 재고가 없는 메뉴를 주문하기 화면에서 어떻게 보여 줄지

## 5. 관리자 화면

관리자 화면은 주문 집계를 보고, 메뉴 재고를 조정하고, 주문을 다음 단계로 넘긴다. 헤더의 관리자를 누르면 이 화면으로 들어온다.

화면은 위에서 아래로 헤더, 관리자 대시보드, 재고 현황, 주문 현황 네 영역이다.

### 5.1 헤더

주문하기 화면과 같은 헤더다. 이 화면에서는 관리자만 테두리로 선택된 상태임을 보여 준다. 주문하기를 누르면 주문하기 화면으로 이동한다.

### 5.2 관리자 대시보드

제목은 `관리자 대시보드`다. 아래에 주문 수를 한 줄로 보여 준다.

`총 주문 {총수} / 주문 접수 {접수 수} / 제조 중 {제조 수} / 제조 완료 {완료 수}`

| 항목 | 집계 |
| --- | --- |
| 총 주문 | 저장된 주문 전체 수 |
| 주문 접수 | 상태가 주문 접수인 주문 수 |
| 제조 중 | 상태가 제조 중인 주문 수 |
| 제조 완료 | 상태가 제조 완료인 주문 수 |

와이어프레임 예시는 `총 주문 1 / 주문 접수 1 / 제조 중 0 / 제조 완료 0`이다. 주문이 없으면 네 값 모두 0이다. 주문 상태가 바뀌거나 새 주문이 생기면 집계를 바로 다시 보여 준다.

### 5.3 재고 현황

제목은 `재고 현황`이다. 주문하기 화면의 메뉴 3개를 카드로 한 줄에 나란히 놓는다.

카드 내용은 위에서 아래로 메뉴 이름, 재고 수량, 증가 버튼, 감소 버튼이다.

| 메뉴 이름 | 처음 재고 |
| --- | --- |
| 아메리카노(ICE) | 10개 |
| 아메리카노(HOT) | 10개 |
| 카페라떼 | 10개 |

- 수량은 `{수량}개`로 보여 준다. 예: `10개`
- `+`를 누르면 해당 메뉴 재고가 1 늘어난다.
- `-`를 누르면 해당 메뉴 재고가 1 줄어든다.
- 재고가 0이면 `-`는 누를 수 없다.
- 버튼을 누른 직후 카드의 수량을 다시 보여 준다.

### 5.4 주문 현황

제목은 `주문 현황`이다. 주문하기 화면에서 저장된 주문을 목록으로 보여 준다. 최신 주문이 위에 온다. 주문이 없어도 이 영역은 유지하고, 목록만 비어 있다.

한 줄은 왼쪽부터 주문 시각, 주문 내용, 금액, 상태 버튼이다.

와이어프레임에 그려진 주문 예시다.

| 주문 시각 | 주문 내용 | 금액 | 상태 버튼 |
| --- | --- | --- | --- |
| 7월 31일 13:00 | 아메리카노(ICE) x 1 | 4,000원 | 주문 접수 |

표시 규칙:

- 주문 시각은 `M월 D일 HH:mm`이다. 연도는 보여 주지 않고, 시는 24시간제다.
- 주문 내용의 메뉴 한 개는 `{메뉴 이름} x {수량}`이다. 옵션이 있으면 주문하기 화면 장바구니와 같은 이름으로 보여 준다. 예: `아메리카노(ICE) (샷 추가) x 1`
- 한 주문에 메뉴가 여러 개면 쉼표와 공백으로 한 줄에 잇는다. 예: `아메리카노(ICE) (샷 추가) x 1, 아메리카노(HOT) x 2`
- 금액은 그 주문의 총 금액이며, 천 단위를 구분하고 `원`을 붙인다.

### 5.5 주문 상태

주문은 저장되는 순간 `주문 접수`다. 상태 버튼의 문구는 현재 상태 이름이다. 버튼을 누르면 다음 상태로 한 단계 넘어가고, 대시보드 집계도 함께 바뀐다.

| 현재 상태 | 버튼 문구 | 버튼을 누른 뒤 |
| --- | --- | --- |
| 주문 접수 | 주문 접수 | 제조 중 |
| 제조 중 | 제조 중 | 제조 완료 |
| 제조 완료 | 제조 완료 | 더 이상 누르지 못한다 |

제조 완료인 주문은 목록에 그대로 남는다.

### 5.6 화면 상태

| 상태 | 대시보드 | 재고 현황 | 주문 현황 |
| --- | --- | --- | --- |
| 주문이 없을 때 | 총 주문 0 / 주문 접수 0 / 제조 중 0 / 제조 완료 0 | 메뉴별 현재 재고 | 빈 목록 |
| 주문이 있을 때 | 상태별 주문 수 | 메뉴별 현재 재고 | 최신 주문이 위 |

### 5.7 이 화면의 범위

이 화면 요구사항에 포함하는 것:

- 주문 수 집계
- 메뉴 재고를 1개씩 늘리거나 줄이기
- 주문 목록 표시와 상태 진행(주문 접수, 제조 중, 제조 완료)
- 헤더에서 주문하기 화면으로 이동

이 문서 다음에 따로 정할 것:

- 서버 API의 경로와 요청 형식
- 주문 저장 시 재고를 자동으로 줄일지
- 재고가 0인 메뉴를 주문하기 화면에서 어떻게 보여 줄지
